# DocumentChat AI

DocumentChat AI is a Streamlit Retrieval-Augmented Generation (RAG) demo. It
answers questions from bundled demo knowledge and PDF/TXT documents uploaded
by the current browser session. The bundled MileMate facts are fictional demo
data, not verified real-world claims.

## Architecture and retrieval flow

1. Streamlit initializes one persistent ChromaDB collection named
   `milemate_knowledge` and loads the embedding model once per server process.
   Bundled documents missing from the collection are indexed during that
   initialization.
2. `rag_pipeline.py` extracts selectable PDF text with pypdf and TXT text using
   UTF-8. Scanned PDFs without a text layer are not OCR-processed.
3. Extracted text is split into approximately 800-character chunks with about
   150 characters of overlap. Chunk metadata records the source filename and
   PDF page number when available.
4. `sentence-transformers/all-MiniLM-L6-v2` creates local text embeddings;
   Groq is not used for embeddings.
5. ChromaDB stores vectors using cosine distance. Each question retrieves at
   most four chunks, and the default relevance filter omits chunks with
   cosine distance greater than `0.70`.
6. If no chunks pass retrieval, the app returns a not-found response without
   calling Groq. Otherwise it sends the retrieved context and question to the
   configured Groq chat model.
7. The system prompt requires document-grounded claims, treats retrieved
   instructions as untrusted, avoids fabricated citations, distinguishes
   supported facts from labelled inferences, and says when evidence is
   insufficient. It contains a grounded-answer example and a not-found
   example.
8. Source filenames and page numbers displayed under answers are taken from
   the retrieved chunks, not generated by the model.

## Configuration and secrets

Copy `.env.example` to `.env` locally and set:

- `GROQ_API_KEY` — your GroqCloud API key.
- `GROQ_MODEL` — a currently available chat model ID selected in your
  GroqCloud console.
- `CHROMA_DB_PATH` — local ChromaDB persistence directory.
- `EMBEDDING_MODEL` — local sentence-transformers model identifier.

Never put a real key in source code, commit `.env`, or paste a key into chat.
`.gitignore` excludes `.env` and other local secret files. `.env.example`
contains placeholders only. For Render, set the Groq variables in the
service's environment settings; `render.yaml` marks them as values to enter
privately in the Render dashboard.

## Local setup

Windows PowerShell, from the project root:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
code .env
```

Fill in `GROQ_API_KEY` and `GROQ_MODEL` in the local `.env` file. Then check
the environment and launch:

```powershell
python -m pip check
python -m pytest
streamlit run app.py
```

The app listens on Streamlit's local default port `8501`. Streamlit's upload
limit is set to 20 MB per file in `.streamlit/config.toml`.

## Tests

Run the complete suite from the project root:

```powershell
python -m pytest -v
```

ChromaDB integration tests use pytest temporary directories and deterministic
test embeddings; they do not call Groq or alter the application's local
database. App tests mock Groq API calls.

## Render deployment

The included `render.yaml` defines a Python 3.12 Render web service using the
Standard compute plan (1 CPU, 2 GB RAM). This is a paid plan selected because
the local embedding model and PyTorch can exceed the memory available on
Render's 512 MB Free/Starter plans. Review current Render pricing before
creating the service. In Render:

1. Push this project to a Git repository, including the `knowledge_base/`
   directory and `render.yaml`.
2. Create a new **Blueprint** in Render and select that repository.
3. Enter `GROQ_API_KEY` and `GROQ_MODEL` when prompted, or add them to the
   service's Environment settings. Choose the model ID from your current
   GroqCloud console; no default chat model is embedded in the deployment
   configuration.
4. Deploy the service. Render runs the build and start commands below.

Build command:

```sh
python -m pip install --no-cache-dir -r requirements.txt
```

Start command:

```sh
python -m streamlit run app.py --server.address 0.0.0.0 --server.port $PORT --server.headless true
```

The start command binds Streamlit to all interfaces and Render's supplied
`PORT`. The model and Chroma collection are initialized once per running
process. On a fresh instance, the bundled knowledge base is embedded and
indexed automatically; subsequent questions reuse that index.

### Storage and deployment limitations

- The Blueprint does **not** configure a persistent disk. Its filesystem and
  `./chroma_db` contents are ephemeral even though the selected compute plan
  is paid. Bundled knowledge is re-indexed from the committed files after a
  restart/redeploy when the collection is empty. Add a Render persistent disk
  and point `CHROMA_DB_PATH` at its mount path only if durable user data is
  required; attached disks add cost and affect scaling/deploy behavior.
- Uploaded documents go into a separate ChromaDB collection for the current
  Streamlit session, so their retrieved contents are not mixed with another
  session's uploads. They are stored on the service filesystem and **are not
  guaranteed to survive a restart, redeploy, or instance replacement**. On
  the local machine, they remain in the local ChromaDB directory until that
  directory is removed. This demo does not provide durable user-upload
  storage, account authentication, or user-managed deletion.
- Each Render instance has its own ephemeral ChromaDB. If the service is
  scaled to multiple instances, each instance may need to build its own
  bundled index and session uploads will not be shared between instances.
- Sentence-transformers/PyTorch and first-run model downloads add build,
  startup, memory, and network cost. A small/free instance may be slow or run
  out of memory; use a suitable paid instance for sustained use and test the
  cold start before publishing broadly.
- The first request after a service restart can take longer while the local
  embedding model and bundled index initialize.
- This is a demo, not a hardened multi-tenant document service. Do not upload
  sensitive documents. Add authentication, durable storage, quotas, and
  operational monitoring before using it with private user data.

## Main files

- `app.py` — Streamlit interface, session-scoped upload collection,
  retrieval-to-Groq flow, prompt, and source display.
- `rag_pipeline.py` — PDF/TXT extraction, chunking, local embedding,
  persistent Chroma indexing, ingestion, and retrieval.
- `config.py` — environment loading, model/key validation, and storage paths.
- `verify_groq.py` — optional minimal Groq connectivity check.
- `render.yaml` — Render Blueprint configuration.
- `.streamlit/config.toml` — Streamlit server and upload settings.
